## 🙋 How to Take Part

1. Check the **Upcoming Events** table
2. Open the event's folder for the schedule, requirements, and registration details
3. Join the organization's channels for announcements: [add your channel link]
4. Show up prepared, with your own lab environment where required

## 🧑‍🔧 Propose or Host an Event

Have an idea? Open an issue titled `Event Proposal: <name>` with:

- Event type and topic
- Target audience and difficulty
- Proposed date, duration, and format (online or in person)
- What you need from the organization
- Who will host or run it

A maintainer will review it. See [Workflow](https://github.com/Ghost-Protocol-Lab/Damn_Practical_Workflow) for how decisions are made.

## 📁 Event Folder Structure

```
events/
└── YYYY-MM-DD_event-name/
    ├── README.md        # overview, schedule, requirements
    ├── resources/       # slides, labs, cheat sheets
    ├── challenges/      # for CTFs (kept private until the event ends)
    └── retro.md         # what worked, what didn't, what's next
```

## ✅ Event Checklist

**Before**
- [ ] Define goal, audience, and format
- [ ] Set up labs and test everything end to end
- [ ] Publish the event folder and announce it
- [ ] Prepare rules and a code of conduct

**During**
- [ ] Start on time and share the rules
- [ ] Record or take notes where appropriate
- [ ] Keep help channels open

**After**
- [ ] Publish resources and write-ups to [Write-Ups](https://github.com/Ghost-Protocol-Lab/Damn_Practical_Write_Ups)
- [ ] Collect feedback
- [ ] Write the retro in `retro.md`

## 🤝 Code of Conduct

Be respectful and keep it ethical. Harassment, cheating, and attacking systems outside the agreed scope are not tolerated. All offensive activity stays inside the event's lab environment and authorized scope.
